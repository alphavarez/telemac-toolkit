# TELEMAC Toolkit roadmap

Plan after 0.4.1 (October 2026), released as 0.5.0 (November 2026). Each step ends in a release that is tested on a real project before the
next one starts. Sizes: S = days, M = one to two weeks, L = several weeks.

Principles:

- **QGIS + Python only stays true.** New engines (Gmsh, MMG) are optional; the built-in mesher remains the
  default and keeps improving.
- **Measure before investing.** Engine work starts with a benchmark against meshes made in Blue Kenue and
  Salomé, and is judged by how TELEMAC runs on each mesh, not only by element angles.
- **No rework.** Work that depends on the engine choice (junctions, stretched elements) waits until the
  engine decision.

## Step 1 — River helper and speed (M) — done in 0.5.0

Remaining from this step: fewer Delaunay rounds (the triangulation library itself is now half the meshing
time, where step 4's Gmsh would help more).

- **River helper**: a river reach from a centreline and a width (constant or from an attribute), or from two
  bank lines, plus a DEM. Writes the left bank, right bank and axis with matched vertices, ready for
  *Generate mesh*.
- **Automatic boundary lines**: where the channel crosses the domain outline, an inflow or outflow line is
  placed across the section. The higher bed is the inflow (prescribed Q), the lower one the outflow
  (prescribed H).
- **Speed fix**: the edge-flip loop that takes 35 % of the meshing time is vectorised; fewer Delaunay
  rounds (4 today).
- **Quality-guaranteed method** (built-in): Delaunay refinement until every angle is above a target
  (25–30°), as a second method next to the current one.

## Step 2 — Boundary conditions (S–M) — done in 0.5.0

The boundary editor on the mesh stays with the editing work of step 3.

- **Rating curve** for the outflow: normal depth from the DEM cross-section, Manning's n and a slope taken
  from the DEM, written as TELEMAC's stage-discharge curves file.
- **Hydrograph import** from CSV or Excel (for example HEC-HMS output) into the `.liq` file, with time and
  unit conversion.
- **Checks**: every liquid boundary has a value; TELEMAC boundary numbers labelled on the map.
- **Initial condition**: hotstart from a constant water level or from normal depth along the reach.
- **Boundary editor on the mesh** and a **steering file template** (from the earlier roadmap).

## Step 3 — Editing and snapping (M) — done in 0.5.0

Snapping uses QGIS's own snapping settings; matching the tools of the Land Cover and Curve Number plugins
waits for their source. Found on the way: the steering file now uses the NERD scheme for velocities (a
river inflow on a fine mesh dried out with characteristics).

- **Editing round trip**: an existing TELEMAC mesh opened as an editable copy, edited with QGIS's mesh
  editing tools (add or remove vertices, flip edges, split faces, move vertices), saved back to SELAFIN
  with bottom and friction interpolated for new nodes and the `.cli` numbering recomputed.
- **Re-mesh inside a polygon**: a bad area of an existing mesh is regenerated by the plugin's mesher and
  stitched to the surrounding nodes.
- **Snapping preset** for the mesh project (vertex and segment snapping on domain, banks and boundary lines,
  topological editing), working like the snapping of the Land Cover and Curve Number plugins.
- **Drawing validation**: banks that do not end on the outline, boundary lines off the outline.

## Release 0.5, then 1.0

Real-project testing of steps 1–3. Then `experimental=False` (1.0 stable) once a real river case has run end
to end without workarounds.

- **3D view button** (S): bottom as terrain, free surface as a coloured surface, exaggeration and time
  linked, in QGIS's 3D map view (drawn by the GPU through QGIS, no new dependency).

## Step 4 — Benchmark and meshing engines (M) — done in 0.5.0

The benchmark against Blue Kenue and Salomé meshes is the comparison tool: it needs the user's own cases (the
same input lines meshed in each program), which it reads (.t3s, SELAFIN, 2DM).

- **Import of Blue Kenue line files** (`.i2s`, `.i3s`, `.t3s`), so the same input lines can be meshed by
  every engine.
- **Benchmark suite**: the same cases meshed by the built-in methods, Gmsh, Blue Kenue and Salomé.
  Compared: minimum angles and the share below 30°, size grading between neighbours, node count, meshing
  time, and TELEMAC behaviour (stable time step, differences in results).
- **Pluggable engines**: one input, one set of outputs, engine chosen in the panel.
- **Gmsh backend** (optional pip install, GPLv2+): Delaunay, Frontal-Delaunay, MeshAdapt, BAMG,
  quadrilateral recombination.
- **Method list** named by purpose: *Balanced*, *Highest quality*, *Fastest (large models)*, *Stretched
  along channels*, *Quadrilaterals (other programs)*, and a target minimum angle. Methods whose engine is
  missing are greyed out with the install command. TELEMAC output is always triangles.

## Step 5 — DEM adaptability and MMG (L) — done in 0.5.0

MMG runs as its standalone program (mmg2d_O3) through its text files: its Python package needs a newer NumPy
than some QGIS installations ship. The terrain refinement leaves structured channels as they are; on rivers the
channel's own resolution matters most (see the guide's example).

**Terrain-adaptive size field** (NumPy, works with every engine):

- Refinement where linear triangles would misrepresent the DEM by more than a tolerance (for example
  5 cm): banks, levees, steep slopes; coarse elements on flat floodplain.
- Size from slope and curvature, and from the local channel width (approximate medial axis).
- A limit on how fast the size changes between neighbours (gradation).

**Breaklines from the terrain**:

- Thalwegs, bank tops, levee and road crests extracted from the DEM as constraint lines.
- Contours and DXF lines (read by QGIS) as constraint lines.
- Bank lines of structured channels snapped to the bank-top breaklines.

**MMG optimise / adapt step** (optional pip install; MMG is LGPL):

- Quality optimisation of any mesh.
- Adaptation to the DEM with elements stretched along channels.
- **Solution-adaptive loop**: run TELEMAC, refine where depth or velocity gradients are high, coarsen
  elsewhere, run again.

## Step 6 — Hybrid meshes (M) — done in 0.5.0

- **Junctions**: several centrelines in the River reach tool; strips stop short of each junction, whose channel
  area is meshed with triangles along its banks (guide lines), corners kept. Tested in TELEMAC on a 60° confluence.
- **Variable width**: the nodes across follow the width, one row of triangles per change (at least 7 across).
- **Bends**: only the sections in tight bends are turned; inner-bank cells at least the spacing / ratio.
- **Transition checks**: cell ratio and skew of each strip, size jumps at strip edges, strip ends on the outline
  without (or only partly under) a boundary line.

## Laboratory and synthetic shapes — done in 0.5.0

- Channels composed from segments (bends, elbows, sine-generated and Kinoshita meanders, tapers, expansions,
  steps), cross-sections (compound, V, parabolic, asymmetric, custom), drawn centrelines and TXT/CSV/DXF imports
  (centrelines or outlines).
- The mesh boundary follows the drawn outline within a set distance (5 % of the element size by default);
  outlines digitized with many close, zigzagging vertices no longer hang the mesher.
- SELAFIN coordinates kept exact in map coordinates (integer origin above 4 km); double precision as an option.
- Drawing checks against the element size with safe fixes; mesh type choice; hover tips readable with dark
  themes; fixes (overwriting a mesh loaded in QGIS, the local CRS named in QGIS, re-meshing in map coordinates).
- **Next**: obstacles and structures placed along a flume: cylinders and bridge piers, abutments, groynes
  (single or series), lateral cavities, islands, sills, bumps and weirs, each with local refinement.
- **Next after that**: named benchmark presets with their published dimensions (bends and meanders, junctions,
  structures and steps, dam breaks).

## Within the current core (decided October 2026)

A proposal for a 0.9/1.0 rewrite (a bundled C++ engine for 5-10 million nodes, a 3D mesher for TELEMAC-3D,
a ParaView state file, aggressive snapping for single precision) was reviewed. The facts that decided it:

- **No compiled code in the plugin.** The QGIS plugin repository does not approve plugins that use binaries
  (plugins.qgis.org/docs/approval). A compiled engine would also need one build per OS, CPU and Python version
  (or a C-ABI library through ctypes), macOS signing and notarisation, and can be blocked by antivirus and
  corporate filters. The plugin stays pure Python + NumPy; heavy engines stay optional pip packages (gmsh).
- **Where the time goes (measured, Balanced method).** About 129 000 nodes in 23 s (0.3 GB), 509 000 nodes in
  124 s (about 1 GB): roughly 2.4 s and 2 GB per million nodes, so 2 million nodes take several minutes and
  about 4 GB. The profile shows Python-level overhead, not arithmetic: interior node placement loops, edge sets
  built as Python tuples (`tolist`), duplicate-point removal before the triangulation, point-in-ring tests.
  These can be rewritten in NumPy (sorted int64 edge keys, grid buckets, int32 connectivity) without C++.
  The 2-million node limit is an adjustable safety estimate (0 removes it), not an engine limit.
- **TELEMAC-3D does not read a 3D mesh.** It extrudes the 2D triangle mesh into prisms itself
  (NUMBER OF HORIZONTAL LEVELS, MESH TRANSFORMATION: sigma, fixed or user-defined planes). The 3D work is
  set-up and post-processing, not 3D meshing.
- **ParaView has no built-in SELAFIN reader** (the old Serafin plugin had to be compiled per ParaView
  version). Results go to formats it reads natively (a .pvd series of .vtu files, written with NumPy), and the
  pipeline as a Python state file (.py), which survives ParaView upgrades better than the XML .pvsm.
- **Single precision is solved** by the integer origin of 0.5.0 (0.01 mm). The overlaps, collapsed nodes and
  slivers met so far came from geometry (near-duplicate vertices, zigzags, near-touching rings) and from
  tolerance bugs, fixed in 0.5.0. What remains is checking the drawing, not more precision.

Adopted, in this order (each a small release, tested in QGIS 3.44, QGIS 4 and TELEMAC):

1. **Clean drawing and precision options** (done in 0.5.0): Check the drawing reports near-duplicate vertices, edges much
   shorter than the element size, spikes, self-intersections, rings that nearly touch and shared edges that
   are not snapped, with a one-click fix where it is safe (removeDuplicateNodes, makeValid) and the place
   shown on the map; double precision SELAFIN (SERAFIND) as an option, with the matching steering keywords.
2. **Speed pass in NumPy**: a benchmark script (time and memory at 0.1, 0.5, 1 and 2 million nodes), then the
   hot spots above rewritten; int32 connectivity; target 2 million nodes in about a minute and half the memory.
   For larger meshes, Gmsh (optional package) fills the inside.
3. **Export to ParaView**: results (2D, and 3D as prisms from ELEVATION Z) as .pvd + .vtu, one file per time
   step so ParaView reads them one at a time, and a Python state file with Warp By Scalar (free surface) and
   Threshold (bed shear stress from the shear velocity); ParaView found and opened if installed.
4. **TELEMAC-3D set-up**: number of planes and their distribution (sigma, fixed levels), a cross-section preview
   of the planes along a profile line, a steep-bed check for sigma layers (rx0 ratio per edge), steering file
   and vertical velocity profiles on the boundaries; 3D results (planes, vertical sections) in the Results panel.

Then the laboratory items above (obstacles and structures, benchmark presets).

## Later

- **ML dataset export**: TELEMAC results written as ML-ready files (node coordinates, bottom, friction, mesh
  connectivity, boundary inputs, time series of depth and velocity) for training surrogate models (graph
  neural networks) on a GPU outside QGIS; predictions read back as a result for the Results panel.
- **Parallel-ready cases**: number of processors and partitioning settings in the steering file template.
- **Export for GPU screening solvers** (raster-based): optional, only if screening runs are needed.
- **Analysis**: arrival time, flood duration, hazard (h·V), scenario differences, listing parser, two-run
  comparison in the calculator.
- **Results**: partitioned results, streamlines, animation export.
- **Model features**: culverts and sources.
- **Other programs**: HEC-RAS geometry file writer.

## Not planned

- **Compiled code bundled in the plugin** (C++, Cython): not accepted by the QGIS plugin repository; see
  "Within the current core" above.
- **A 3D mesher for TELEMAC-3D**: TELEMAC-3D builds its prisms from the 2D mesh.
- **GPU code in the plugin**: meshing is limited by Python overhead, interpolation and the calculator by
  memory and disk; GPU libraries (CuPy) need NVIDIA and CUDA and would exclude Mac users.
- **JIGSAW** (custom proprietary licence) and **Triangle** (not free for commercial use) as engines.
